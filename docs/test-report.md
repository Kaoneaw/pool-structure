## ฟังก์ชันที่ตรวจ

- ตัวอย่าง 5 × 10 ม. ลึก 1.2–1.8 ม.: คอนกรีตผนัง 9.24 ม³ พื้น 14.04 ม³ รวม 23.28 ม³ น้ำที่ H=1.2 ม. จากพื้นด้านลึก 45 ม³ แบบหล่อผนัง 92.4 ม² ตรวจเทียบกับ `reference/geometry-example.json` ซึ่งเป็นข้อมูลคำนวณมือ
- พื้นราบ น้ำเต็ม/น้ำหมด น้ำต่ำกว่าด้านตื้น ความต่อเนื่องตรงขอบเขตส่วนเปียก และขอบสระที่ไม่ซ้ำกับผนัง
- สระลึกมาก น้ำใต้ดินสูง สระว่าง และผนังบาง: ตรวจว่าปริมาณเป็น finite และไม่มีผลผ่านทางโครงสร้างที่สร้างขึ้นเอง **ไม่ได้หมายถึงโครงสร้างปลอดภัย**
- ปฏิเสธค่าติดลบ NaN Infinity ฟิลด์ขาด เวอร์ชัน JSON ผิด และรูปทรงที่แนวลาดต่อผิวนอกตัดขอบบน
- Backup/restore, escaping CSV/spreadsheet formula, เปอร์เซ็นต์ความต่างและฐานเป็นศูนย์
- ผลรวมปริมาตรทุกองค์ประกอบ IFC เท่ากับปริมาณรวม
- IFC4 ที่ส่งออกเปิดด้วย web-ifc 0.0.78 ได้ 4 IfcWall + 1 IfcSlab มี mesh, hierarchy, Qto และวัสดุ ไม่ใช่ตรวจเฉพาะ string หรือส่วนหัว

## เบราว์เซอร์

1. เปิด WebGL แก้ขนาดและคงค่าเมื่อโหลดใหม่ สลับโหมดมืด
2. ข้อมูลไม่ถูกต้องไม่เปลี่ยนโมเดล; ไม่ส่งออกฟอร์มที่แก้แล้วยังไม่อัปเดต
3. IFC ผ่าน Worker, tree ตามชนิด/พื้นที่, Qto/วัสดุ, เลือกค่านำเข้าฟอร์ม, หน้าตัด/โปร่งใส
4. PDF สองหน้า ตั้งสเกล วัด 5.000 ม. ซูม วางใน 3D และแยกสเกลแต่ละหน้า
5. ดาวน์โหลด CSV/JSON/IFC และรายงานพิมพ์มีคำเตือน
6. กู้คืน JSON ผิดเวอร์ชัน และป้องกัน HTML ในชื่อโครงการ
7. ส่วนหัว IFC ผิดแจ้งเป็นภาษาไทย
8. มือถือ 390 × 844 ไม่มี horizontal overflow และสลับแท็บได้
9. ดัก network requests ระหว่างดู PDF/IFC: ไม่มีการส่งไฟล์ ไม่มี external request
10. เปลี่ยน PDF หลังวัดและระหว่างตั้งสเกล: เปิดไฟล์ใหม่ได้ สเกล/ค่าวัด/ช่องตั้งสเกลเดิมไม่ติดข้ามเอกสาร

ครั้งแรกมี test selector ชื่อวัสดุ `Concrete` ตรงกับทั้ง Name และ Category จึงเลือกเป้าหมายให้ชัดแล้วรันผ่าน ไม่ได้ปิด assertion หรือข้าม test

## ยังไม่ทดสอบ / ยังบล็อก

- การคำนวณตามมาตรฐาน กำลังดัด/เฉือน แรงดัน M/V เหล็กขั้นต่ำ รอยร้าว uplift bearing settlement แผ่นดินไหว และน้ำหนักเหล็ก: **ยังไม่ implement** จึงไม่ใช่ผลผ่าน
- Regression กับ RCTankC: **ไม่มีคู่ผลอ้างอิง** ไม่รายงาน % ความต่าง และไม่ได้รัน `.exe`
- ฉบับล่าสุด/การบังคับใช้มาตรฐานไทยและ ACI: แหล่งทางการถูก proxy 403 ดู `standards.md`
- ไฟล์ IFC ขนาดใหญ่จริง, geometry ทุกชนิด, PDF เข้ารหัส, browser อื่น, buildingSMART certification: **ยังไม่ได้ยืนยัน** Worker ช่วยแยก parsing แต่ไม่รับประกันหน่วยความจำหรือความเร็วทุกเครื่อง
- GitHub Actions/Pages บน remote: เตรียม workflow แล้ว **ยังไม่ได้ push/deploy** การทดสอบ subpath ในเครื่องไม่เท่ากับการเผยแพร่จริง

ไม่พบข้อผิดพลาดที่ยังไม่อธิบายในความสามารถที่เปิดใช้ แต่โครงการยังไม่ครบระบบตรวจโครงสร้างจนกว่าจะยืนยันแหล่งอ้างอิงและสมมติฐานวิศวกรรม

## การทำงานต่อและแพ็ก static

- พบข้อผิดพลาดจริงเมื่อเปิด PDF ไฟล์ที่สอง: pdf.js 6 ไม่มี `PDFDocumentProxy.destroy()` ต้องใช้ `PDFDocumentLoadingTask.destroy()` แก้ lifecycle และล้างสถานะการวัดเมื่อเปลี่ยนเอกสารแล้ว
- เพิ่ม test ที่ทำให้เห็นความล้มเหลวเดิมก่อนแก้ และรันครบ 13 unit/integration + 10 browser tests ผ่านหลังแก้
- สร้าง `artifacts/pool-studio-static.zip` รวม build, ฟอนต์, workers, WASM, licenses, เอกสารสถานะ และคู่มือภาษาไทย ไม่มี source `.exe` หรือข้อมูลผู้ใช้ในแพ็ก
- ตรวจ CRC และ SHA-256 ของทุกไฟล์ในแพ็ก และลองแก้ `index.html` ในสำเนาแพ็ก: ตัวตรวจปฏิเสธด้วย SHA-256 mismatch ตามคาด
- แตกแพ็กจริงแล้วเสิร์ฟใต้ `/pool-structure/`: เปิด 3D, IFC4 5 องค์ประกอบ, สร้างรายงาน PDF แล้วเปิดเป็นแบบอ้างอิงสองครั้งได้ ไม่มี HTTP/page error และไม่มี request ไปโดเมนภายนอก
- การตั้งค่าโดเมนถูกบันทึกแล้ว แต่ runtime ยังได้ CONNECT 403 แม้ทดสอบนอก sandbox: ดู [ผลวินิจฉัย](network-diagnosis.md) ไม่ใช่เหตุให้ขอเพิ่มโดเมนเดิมอีก
- แพ็ก static เป็นไฟล์สำหรับดาวน์โหลด ยังไม่ได้เผยแพร่บน remote
